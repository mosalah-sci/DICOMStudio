# ADR-019: Application Action Architecture

Status: Accepted
Date: 2026-08-03

## Context

The shell needs a menu bar, toolbar and keyboard shortcuts that behave like a
commercial workstation, while features from later milestones (DICOM loading,
zoom, measurements) do not exist yet.

## Decision

- Every action is described declaratively in an `ActionCatalog` (identifier,
  text, shortcut, status tip, icon, enabled state) and created once with a
  single consistent icon set.
- Enabled actions must register a handler at construction time; unavailable
  actions remain visible but disabled so the interface communicates future
  capability.
- Menu and toolbar assembly is a pure function of the catalog.
- App-level coordination that outlives a single widget (theme switching,
  persistence) lives in the Application layer (`ThemeManager`) behind ports;
  Presentation glues it to the UI.

## Consequences

- Shortcuts, tooltips and icons live in one reviewable place.
- Later milestones enable actions by registering real handlers without
  touching the window shell.
- No dead actions can be added accidentally: the catalog fails fast.
