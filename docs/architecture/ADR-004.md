# ADR-004: Background Execution Strategy

Status: Accepted
Date: 2026-08-03

## Context

Long-running operations (study scanning, pixel loading, export) must never
block the UI thread, and widgets must never be touched from worker threads.

## Decision

- Background work is executed through a `BackgroundTaskRunner` port owned by
  the Application layer.
- The implementation is built on Qt `QThreadPool` and lives in Infrastructure.
- Results and progress are delivered through typed signals on objects with
  an affinity to the event loop; worker threads never access widgets.

## Consequences

- The threading mechanism is replaceable without touching use cases.
- Future milestones (scanning, loading, caching) reuse one pattern.
- The implementation arrives with its first consumer (DICOM Discovery).
