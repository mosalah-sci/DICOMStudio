# Architecture Decision Records

Architecture Decision Records capture important architectural decisions so
that future contributors understand not only *what* the codebase does, but
*why* it is structured the way it is.

## Process

- Each ADR has a unique number and file (`ADR-NNN.md`).
- A decision becomes effective when its ADR is marked **Accepted**.
- Changing a decision requires a new ADR that supersedes the old one.
- The status field always reflects the current state (`Accepted`).
