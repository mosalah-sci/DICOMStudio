# ADR-001: Layered Architecture and Dependency Direction

Status: Accepted
Date: 2026-08-03

## Context

The application must remain maintainable and extensible for many years while
future capabilities (PACS, MPR, 3D, AI, plugins) are added. Unrestrained
dependencies between modules would make such growth impossible.

## Decision

The codebase uses four layers with strict inward dependency direction:

```
Presentation → Application → Domain ← Infrastructure
```

- **Presentation** (Qt) depends on Application.
- **Application** depends on Domain.
- **Infrastructure** implements the ports declared by Domain and Application.
- **shared/** provides leaf-only helpers importable by every layer.

Cross-layer dependencies outside this direction are architecture violations.

## Consequences

- Architectural boundaries are enforced during code review and by tooling.
- Domain and Application remain framework-free and unit-testable in isolation.
- Every new feature must fit into exactly one layer.
