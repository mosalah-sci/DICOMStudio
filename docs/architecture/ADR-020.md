# ADR-020: Windows Packaging and Distribution Strategy

Status: Accepted
Date: 2026-08-04

## Context

The application is feature-complete and must be distributed to end users as a
professional Windows product. Python must not be a prerequisite, and the
distribution needs to cover a standalone executable, an installer and a
portable archive while keeping the release process reproducible.

## Decision

- **Standalone build**: PyInstaller produces an onedir distribution
  (`dist/DICOMStudio/`) from the same source tree that ships as a wheel. The
  launcher is a windowed (`console=False`) executable named `DICOMStudio.exe`
  that embeds the application icon and a generated Windows version resource.
- **Application icon**: A multi-resolution `DICOMStudio.ico` is generated from
  `packaging/app-icon.svg` by `scripts/make_icon.py` and is shared by the
  executable, the installer and the Start Menu/desktop shortcuts.
- **Version resource**: `packaging/version_info.txt` is regenerated by
  `scripts/make_version_info.py` from the single version source
  (`_version.py`) and the shared constants, so the executable metadata can
  never drift from the packaged version.
- **Installer**: Inno Setup compiles a professional per-user installer
  (`dist/installer/DICOMStudio-<version>-Setup.exe`) that installs
  the standalone folder, creates Start Menu shortcuts, offers an optional
  desktop shortcut, registers `.dcm` file associations and provides a full
  uninstaller.
- **Portable archive**: `scripts/build_portable.ps1` zips the standalone folder
  into `DICOMStudio-<version>-Portable.zip` for USB/no-install
  use.
- **Release orchestration**: `scripts/release.ps1` runs the test suite, builds
  the standalone app, smoke-tests it, compiles the installer and produces the
  portable archive in one deterministic pass.
- **File associations**: launching the installed app with a DICOM file opens
  its containing directory, matching the folder-based study explorer workflow.
  Shutdown now always closes the window first so a running scan thread is
  stopped before interpreter teardown.

## Consequences

- End users get a runnable application with no Python dependency, branded
  shortcuts, file associations and clean uninstall.
- The three distribution formats share one frozen payload, so behavior is
  identical across standalone, installed and portable use.
- Build tooling (PyInstaller, Inno Setup) is required only on the release
  machine; CI keeps validating formatting, lint, typing and tests.
- Unsigned binaries may be flagged by Windows Application Control / WDAC on
  some managed environments; code-signing is a future hardening step.
