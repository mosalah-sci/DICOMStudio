# ADR-018: Window State Persistence

Status: Accepted
Date: 2026-08-03

## Context

The UI blueprint requires the dock layout and window geometry to persist
between sessions, and startup must not fail because a previous layout file is
corrupt.

## Decision

- Qt serializes geometry and dock state as opaque byte payloads
  (`saveGeometry` / `saveState`); the Presentation layer produces them and
  never interprets them.
- An Application-layer port (`WindowStateStore`) defines the contract; a
  JSON-backed `JsonWindowStateStore` in Infrastructure persists the payloads
  (base64-encoded) under the user config directory.
- Corrupt, missing or unreadable files are ignored and the default layout is
  used, with the failure logged.

## Consequences

- Persistence mechanism is swappable without touching the window code.
- The store is unit-testable without a Qt application.
- A damaged layout file can never prevent the application from starting.
