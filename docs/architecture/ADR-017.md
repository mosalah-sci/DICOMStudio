# ADR-017: Settings Model in the Domain Layer

Status: Accepted
Date: 2026-08-03

## Context

Presentation needs the active theme and settings to build the shell. With the
settings model inside Infrastructure, Presentation (or the Application ports it
depends on) would have to import Infrastructure types, violating the strict
`Presentation → Application → Domain ← Infrastructure` dependency direction
(ADR-001).

## Decision

- The settings model (`Settings`, `LoggingSettings`, `AppearanceSettings`,
  validation) lives in the Domain layer as pure, framework-free data.
- Infrastructure keeps all persistence concerns (TOML loading, merging,
  serialization) in `settings_service.py`.
- Application declares ports (`SettingsStore`, `WindowStateStore`) that
  Infrastructure implements; Presentation depends on these ports only.

## Consequences

- Dependency direction is enforced: Presentation never imports Infrastructure.
- Domain and Application remain framework-free and unit-testable in isolation.
- The settings snapshot is reusable by every layer without coupling to TOML.
